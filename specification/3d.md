# Native 3D rendering

Rays's public 3D model is immutable. `Scene.D3` describes meshes, transforms,
camera state, lighting, materials, textures, depth/stencil/raster intent, and
blending. `Scene.view3d` places that description in a logical viewport. The
effect boundary lowers supported drawings to checked OGPU work and renders them
with Metal.

There is one implementation path:

```text
Scene.D3 + Camera + Mesh
          |
          v
Scene3_native_lowering
          |
          v
Scene_execution -> OGPU -> ogpu_metal -> Metal
```

## Coordinates and viewport

Scene and camera viewports use logical points. Runtime obtains the Metal
drawable's physical dimensions and converts logical viewport edges once at the
native boundary. The resulting Metal viewport and scissor share the same
physical rectangle, including on Retina displays and after resize.

Camera projection uses the logical viewport aspect ratio. Mesh positions and
normals remain model-space values; the lowering packs model-view-projection,
model, normal, eye, material, ambient, and light data into checked native
uniform storage.

## Supported native lowering

The current public native lowering accepts:

- `Scene.D3.Faces` drawings whose mesh topology can be converted to triangles;
- indexed triangle, triangle-strip, and triangle-fan input;
- a complete normal per vertex;
- scoped transforms, face culling, depth compare/write, and supported blend
  modes;
- fixed materials, the scene ambient color, and up to 64 scene lights (more
  is a typed `Too_many_lights` error);
- an optional sampled texture with declared filter/wrap policy;
- one optional shadow map (`Scene.D3.create ?shadow`);
- supported scene sample counts negotiated against the Metal device;
- an optional baked World (`Scene.D3.with_world`): environment background,
  image-based and sun lighting through the path tracer's BRDF and ACES tone
  map, described in [environment.md](environment.md).

Meshes are packed into deterministic vertex and 32-bit index bytes. Immutable
mesh identities feed bounded native mesh and retained-plan caches. Changing a
camera or attachment must reuse draw-bound geometry; changing mesh contents or
device identity must not alias a previous resource.

The render lifecycle retains all buffers, textures, samplers, pipelines, and
attachments referenced by a submission until command completion. Cache
eviction and runtime teardown release resources on the initial domain.

## Typed unsupported surface

The public model remains broader than the currently qualified native lowering.
The boundary returns a typed error for unsupported cases rather than executing
another renderer or silently dropping work. In particular:

- wireframe, vertex, point, line, and otherwise non-triangulable public modes
  are currently rejected by native scene preparation;
- malformed meshes, missing per-vertex normals, invalid viewports, and resource
  failures are rejected;
- more than 64 scene lights is `Too_many_lights`.

Do not describe an API constructor or an isolated Metal capability test as
public Scene3 support. A capability is complete only when public lowering,
runtime execution, ownership, resize/multi-frame behavior, and framebuffer
evidence all agree.

## Scene construction

`Scene.D3.create` validates scene-level sample intent and stores pure nodes.
Primitive conveniences (`box`, `plane`, `sphere`, `icosphere`, `cylinder`, and
`cone`) build ordinary `Mesh.t` values. `mesh`, `instances`, and
`instances_array` share immutable geometry. Scoped constructors compose
transforms and state without mutating following nodes.

`Scene.D3.Private.iter_batches` is the internal renderer boundary. It yields one
drawing descriptor plus an optional borrowed transform array. Public code must
not depend on this private representation or native resource identifiers.

## Camera and interaction

`Camera` owns immutable perspective/orthographic projection and world/view/
screen conversions. `Easy_camera` translates ordered Rays
events into immutable camera state. Pointer capture, focus loss, resize, and
logical coordinates follow the same runtime event contract as 2D/PXUI.

## Validation requirements

Native 3D changes require focused coverage for:

1. exact vertex/index packing and invalid mesh rejection;
2. transforms, normal matrices, depth, culling, blending, texture, light, and
   shadow uniform lowering;
3. logical-to-drawable viewport/scissor conversion at multiple pixel scales;
4. supported sample negotiation and resolve behavior;
5. frames 1, 2, 60, and 600, including resize and attachment replacement;
6. stable mesh/plan cache hits without repeated upload;
7. command-completion ownership and zero live-handle delta after teardown;
8. typed rejection of every public feature not yet lowered;
9. exact or explicitly tolerance-bounded native framebuffer fixtures;
10. the full native link and dependency-direction gates.
