    Today vs proposed

    From tiles in rows to a typed flow

    Today the graph pane lays tiles out top to bottom by input depth and joins them with cubic Béziers. Wires carry geometry only: an Edit_graph.connection is a source, a consumer and an input index. Parameters live in the inspector as literals of each node's schema record, so nothing in the network can drive a value. Vector parameters are flattened into three floats (translate_x, translate_y, translate_z).

    Principles

    Six rules the rest follows from

    Read left to right

    Sources sit on the left, the displayed result on the right. Geometry enters and leaves through the header row, so an unbranched chain is one horizontal wire.

    Points first

    A network is a graph of points. Open only what you are editing. Zoom caps how much each node shows unless you opened it yourself.

    A parameter is an input

    No second system for driving values. A literal, a wire, a wireless bind, an expression and an export all fill the same slot.

    Straight wires, placed on purpose

    Bend points are data you author. They snap to the grid, survive auto-layout, and never enter the program text.

    One key, one meaning

    Verbs are single letters that mean the same thing at every level. The guide shows which ones apply right now, until you stop needing it.

    One document, three views

    The graph is an AST. Canvas, list and text are views of it. Positions, bends, levels, pins and wire visibility are layout, so the text stays clean and diffable.

    Anatomy

    Point, chip, card, full

    A point is the header's colour square grown into a dot; wires meet at its centre and the network reads like a constellation. A chip is the header alone; driven rows attach along its bottom edge and a +2 badge counts them. A card shows the rows that matter (see the exposure rule below) and a + 5 more row. Full shows every row, grouped under folder headers, with rows that are not on the card dimmed.

    o opens one level, p toggles the selection between point and its previous level, ⇧P does that for the whole network, and ⇧O opens everything to cards. Zoom below 50% and nodes show as chips, below 34% as points, except nodes you opened yourself. Drag a wire over any node and it opens to full under the cursor, so hidden rows are droppable too.

    Left to right: Grid is a point, Noise Displace a chip, Swirl a card, Transform full with its folders, Output a point. Press ⇧P twice, or drag from Swirl's output over Output.

    Sockets: shape is structure

    • Square: geometry
    • Circle: one value (float, int, vec3, color)
    • Violet circle: a vec3, splittable into x, y, z
    • Diamond: per-element field (reserved, as in Blender 5)
    • Hollow uses its literal; a dashed ring is a wireless bind

    Wires: colour is type

    • Geometry, 2.4 pt
    • Float, 1.5 pt, with a live value readout
    • Vector, reads out as three numbers
    • Wireless: drawn only while an end is selected or hovered
    • Bend points: Alt-click to add or remove, drag to move

    Node colour: what it makes

    • Makes geometry
    • Makes a number
    • Makes a vector
    • Compound: a graph inside
    • Dashed halo: displayed in the viewport
    Parameters

    The inspector has everything; the card has what matters

    Every parameter row holds a literal and, optionally, a drive: a wire from another node's output, or an expression. A wireless bind is a wire whose visibility is a view flag; an export is a wire from the compound's Inputs node. As with TouchDesigner's parameter modes, the literal survives while the row is driven, so r puts back what you had.

    SOPs such as Noise Displace have many parameters in folders. The inspector keeps showing all of them, grouped the way [@sop.folder] already groups them. The card applies one rule, in this order:

    1 · driven

    A wired, bound or expression row always shows. Hiding it would hide a wire.

    2 · your pin

    s on a row, or ● in the inspector, keeps it on the card or takes it off.

    3 · changed

    A row whose literal differs from the default shows, which is also what the text form prints.

    4 · primary

    Rows the SOP author marks [@sop.primary] show on a fresh node, so a new Noise shows amplitude and frequency.

    Many parameters + more · s · drag over

    Try: Noise Displace shows amplitude, frequency and octaves (changed to 3). Click + 5 more to see every row by folder, point at roughness and press s, then click show fewer: roughness stayed. Drag from Value's output over the card; it opens fully, so you can drop onto falloff radius even though it was hidden.

    Vectors split · xyz

    Try: translate is one violet socket with three fields; scrub any of them. rotate is split, so Sine drives only y. Click the name translate to split it, then drag Combine XYZ's output onto the whole scale row (hidden until the drag opens the card).

    Bind without a wire b

    Try: Sine already drives amplitude wirelessly (the ⌁ row). Select Sine to see the link. Press b: every value row gets a letter; type Swirl's to bind its angle too. Like a Bitwig modulator, a bind is aimed rather than drawn.

    Expression ⇄ nodes = and ƒ

    Try: press the italic ƒ on amplitude to unfold the expression into Math nodes, then press it on the wired row to fold them back. Point at a row and press = to type one, such as abs(sin(t)) * 0.8.

    How the schema says it
    
  
    
    
    Folders and hard ranges already exist in the PPX. Two additions cover the rest: [@sop.primary] marks default card rows, and [@sop.vec3 "offset"] on three consecutive float fields groups them into one vec3 port. The record keeps its three floats, so no cook code changes; Param only gains primary and vec3 metadata on each field.
    
  
    

    type t = {
  amp    : float [@sop.default 0.5] [@sop.label "Amplitude"] [@sop.folder "Noise"] [@sop.primary];
  freq   : float [@sop.default 0.9] [@sop.label "Frequency"] [@sop.folder "Noise"] [@sop.primary];
  seed   : int   [@sop.default 3]   [@sop.folder "Noise"];
  offset_x : float [@sop.default 0.] [@sop.folder "Offset"] [@sop.vec3 "offset"];
  offset_y : float [@sop.default 0.] [@sop.folder "Offset"] [@sop.vec3 "offset"];
  offset_z : float [@sop.default 0.] [@sop.folder "Offset"] [@sop.vec3 "offset"];
} [@@deriving sop_params, sop_node] [@@sop.register]
    

    


    
  Three views
  
    Graph, list and text of one document
    
  
    
    
    Rays Editor already has a list projection behind Space l. The proposal makes it a cycle of three. All three share the selection, the inspector, undo and the display flag, so you can find a node in the list, edit it in the inspector and see the text change without the graph ever moving. Try it with the switch in the prototype's pane header.
    
  
    
  
    
    
    Graph
    For wiring, reading flow and shaping density. Everything on this page. Default view.
    
    
    List
    The trunk as rows, sources first, side inputs indented under their consumer, shared nodes as ↳ link rows. Badges show driven and changed counts. j k move, ↵ jumps to the node in the graph.
    
    
    Text
    The canonical Lisp, read-only. Each binding line selects its node. Toggle qualified names to see what every symbol resolves to. Editing stays in the graph and inspector for now.
    
  
    

    


    
  Keys and guide
  
    A grammar, and a guide that teaches it
    
  
    
    
    Node verbs act on the selection; row verbs (= e r s) act on the row under the pointer, so you point and press without clicking into anything. Tab reads the context: with a node selected it appends after it and ripples the trunk right, with a wire selected it inserts on the wire, with nothing selected it adds at the pointer. . repeats the last add. Letter hints (c, b) label every compatible target with one or two letters, nearest first, so you never aim at a 9-point socket.
    
    
    Guide mode is how the grammar becomes muscle memory. It has four parts, all driven by the same Command table so they never drift from the real bindings:
    
    
      
      
    • Context strip along the bottom of the pane, listing only the keys that apply to what is selected or under the pointer (canvas, node, value node, compound, wire, row, list, text, leader, hints). In Rays Editor this is the status bar.
      • 
      
    • Tooltips after a short dwell on any socket, row, field, wire, bend point or node header, saying what it is and what you can do to it.
      • 
      
    • Which-key after Space, as today, listing the leader's next keys.
      • 
      
    • Key sheet with Space k, plus a HUD that echoes each key you press with its command label. ? turns the strip and tooltips off once you know them.
      • 
    
    
  
    
  
    
  
    How this lands in Leader.keymap
    
  
    
    
    Each row becomes one Editor_core.Command entry with a stable id, scoped to the graph pane, so dispatch, which-key, the Space / palette and the guide strip all read it. The grammar's letters are reserved in every context. World's graph-scoped keys that collide move to free letters: e (dome/light) becomes t, r (reseed) becomes n, p (day cycle) becomes d; [ ] and the digits stay. i, u and f keep today's meaning; f frames the selection, or the displayed node when nothing is selected.
    
  
    

    


    
  Language
  
    Namespaces, contexts, and the ambiguities they settle
    
  
    
    
    Parameters need no namespace of their own. A keyword such as :amp is resolved against the schema of the node it is passed to, the same way an OCaml labelled argument is. The field's name is its stable key; its label is only for display. Node kinds do need namespaces, because the same short name can exist in several places:
    
    
      
      
    • sop/ is the SOP catalog (sop/noise_displace, keyed by today's stable catalog keys).
      • 
      
    • value/ holds math, time and vector nodes. They carry no geometry, so every context can use them.
      • 
      
    • user/ holds this sketch's defgraphs and custom nodes. A library of compounds gets its own prefix, such as terrain_kit/.
      • 
      
    • Later levels add scene/, world/ and, one day, shader/.
      • 
    
    
    
    Every graph and defgraph declares a :context. The context decides which catalog short names resolve to and which port types exist: geometry in sop, objects and transforms in scene. Short names resolve through local bindings, then user/, then the context's catalog, then value/. More than one match is a compile error that asks you to qualify the name. Node kinds and bindings live in separate namespaces, as in a Lisp-2: (grid …) always calls a kind, and a bare grid is always a binding.
    
  
    
  
    
    
    #AmbiguityRule
    
    
      
    01The same short name in two namespaces, such as a defgraph swirl and sop/swirlCompile error at each use: “swirl is ambiguous: user/swirl or sop/swirl”. Write the namespace
    
      
    02A binding named like a kind: grid (grid)Allowed. Call heads name kinds and bare symbols name bindings
    
      
    03A binding named tError. t is context time, declared as a dependency of whatever reads it
    
      
    04A node with several outputsseparate.x picks an output. . and / are reserved in binding names
    
      
    05A geometry input and a parameter with the same nameGeometry inputs are positional. The PPX rejects a node whose slot name equals a field name
    
      
    063 vs 3.0Integer literals fit int and float fields; :rows 2.5 is an error that names the range
    
      
    07Soft and hard rangesOutside a hard bound is an error. Outside the slider range is a warning
    
      
    08Defaults change between catalog versions, and the text leaves defaults outA file pins its catalog (:catalog 2026.09). Upgrading a node whose default changed writes the old default out explicitly
    
      
    09Renaming a node renames its bindingIds are document data, never derived from names, so a rename keeps the id, the wires and the cache
    
      
    10Wire vs wireless, bends, levels, pins, display flagAll layout. None of them changes the program text
    
      
    11BypassMetadata, ^:bypass (noise_displace …), never a parameter
    
      
    12A vector with some components driven:rotate [0 wave 0]. Each component is a literal, an expression or a binding; a split in the graph is implied
    
        
  
    
  
    Canonical form
    
  
    
    
    The printer is deterministic and ignores layout: roots in stable-id order, inputs in port order, defaults left out, math-only drives inline as expressions. Every preset on this page prints, compiles back and prints the same text again, and that round trip becomes a test over every catalog node.
    
  
    
  
    

    


    
  Compile-time sketches
  
    Sketches written in the same Lisp, checked when they build
    
  
    
    
    A sketch can hold its network as text in a [%flow {| … |}] extension. The PPX parses it at compile time and resolves every symbol against the catalog manifest the SOP PPX already generates (passed in through preprocessor_deps). It checks parameter names, types, integer and hard ranges, vector arity, input slots, cycles and ambiguous names. Then it emits ordinary OCaml that builds the Edit_graph through the same factories the editor uses. Errors point at the exact line and column inside the string. Custom nodes declared earlier in the same file are visible because a PPX sees the whole structure, and each one binds to a user/ symbol. Exposing a defgraph as an OCaml function is deferred until after M7.
    
  
    

    (* sketches/terrain/main.ml; names past [%flow] are illustrative *)
module Rings = struct
  type t = { count : int [@sop.default 6] [@sop.primary]; width : float [@sop.default 0.2] }
  [@@deriving sop_params, sop_node] [@@sop.register] [@@sop.name "rings"]
  let build = parameters_build (fun ~label p geo -> ...)
end

let network = [%flow {|
  (graph terrain :context sop
    (let* [grid  (grid :size 4.4 :rows 22)
           rings (user/rings grid :count 8)]
      (output rings)))
|}]
(* network : Sop.Edit_graph.t, already validated *)

(* a typo fails the build, not the run: *)
File "sketches/terrain/main.ml", line 12, characters 31-37:
Error: rings has no parameter :cuont. Did you mean :count?
    
  
    
    
    The editor's text view prints this same syntax, so a network built by hand can be copied into a sketch as source, and a sketch's network opens in the editor as a graph. The editor text stays read-only; the sketch file is where Lisp is written.

  Architecture
  
      One graph core, many contexts
      
  
      
    
      The SOP network, the scene graph, compounds and every later level want the same thing: typed ports, stable ids, drives, a context and a text form. The context-free part is a new library, flow. The SOP context adds it as an overlay on top of the unchanged Edit_graph, so cooking and caching keep working at every milestone. Presentation stays intent-only, as pxui_graph is today.
      
  
      
  
      
    
      rays_editorchangedKeys, guide strip in the status bar, graph/list/text cycle, the value lane before each cook submission, World key remap.
      
    
      pxui_graphchangedLeft-to-right canvas over the unified network (SOP nodes plus value nodes), levels, polyline wires, rows with sockets. Still emits typed requests only.
      
    
      pxui_shellchangedInspector gains card pins, vec3 rows and drive display; Status_bar hosts the guide strip.
      
    
      editor_documentchangedEach network carries a Flow overlay (value nodes, drives, definitions) and a layout record. Presets move to version 3.
      
    
      flow_sopnewThe sop context: network overlay over an unchanged Edit_graph, value lane, compound inlining, canonical printer, program builder used by [%flow].
      
    
      flownewContext-free core: symbols, port types, Expr, value kinds (Time, Value, Math, Combine/Separate XYZ, Remap), value graphs, drives, the s-expression reader, checker and diagnostics. Depends on param only.
      
    
      ppx_rayschanged[@sop.primary], [@sop.vec3], [@@sop.node_slots], and the [%flow] rewriter, which links flow and reads a promoted catalog manifest.
      
    
      paramchangedprimary and vec3 field metadata. Still dependency-free.

      (* lib/flow_sop/network.mli, a sketch; specification/flow.md is normative *)
type port = { node : int; path : string }        (* "amp", "center.y" *)
type drive =
  | Wire of { node : int; output : string }     (* a value node's output *)
  | Expr of Flow.Expr.t                          (* folds to and from Math nodes *)

type t = {
  geometry : Sop.Edit_graph.t;          (* SOP nodes and geometry wires, unchanged *)
  values : Flow.Graph.t;                         (* value nodes and value wires *)
  drives : drive Port_map.t;                     (* the literal in the node record survives *)
  definitions : Definition.t String_map.t;       (* shared compounds, M5 *)
}

(* one edge per destination port, so the destination names the edge *)
type layout = {
  at : (float * float) Int_map.t;  level : Level.t Int_map.t;  pinned : bool String_map.t Int_map.t;
  split : String_set.t Int_map.t;  bends : (float * float) list Port_map.t;  wireless : Port_set.t;
}
      
  
      Two evaluation lanes
      
  
      
    
      Geometry keeps its path: compile the document, submit to Async_cook, cache by cook key. Values get a small pure lane in front of it. Each frame it evaluates only nodes downstream of a time source or of this frame's edits, compares each resolved row with last frame's, and applies the changed ones. An unchanged value leaves the cook key alone, so nothing re-cooks. A drive that reads t marks its consumer time-dependent through Context.Dependencies, which is how time-driven recooks are scheduled today. Each milestone reports tools/bench_rays_editor.exe 200 1000 2000 before and after; no numbers are claimed here.

      Graph, list, text cycle. Flow.Sexp printer and reader with the namespace rules. Text view read-only.

      • Print, read, print is the identity for every catalog node and sketch preset

  Decisions
  
      Decided defaults
      
  
      
    
      Canonical names in the text view
      Short names read better; qualified names never change meaning when a catalog grows.
      DecidedShort names in the view with the qualified toggle, and qualified names in saved files and [%flow] errors.
      
    
      Compound reuse
      Copies per instance, or shared definitions like Houdini digital assets?
      DecidedShared definitions with an explicit “make unique”. One definition is one defgraph.
      
    
      Primary rows
      Should SOPs without [@sop.primary] show all rows or none on a fresh card?
      DecidedThe first folder's rows, until the author marks primaries. No card starts empty.
      
    
      World keys
      e r p [ ] and digits are World shortcuts in graph scope today.
      DecidedMove the three colliding letters: e→t, r→n, p→d. The grammar's letters are reserved in every context.
      
    
      Catalog pinning
      Text leaves defaults out, so a default change could alter old files.
      DecidedA :catalog version per file, with upgrades that write changed defaults out explicitly.
      
    
      Fields
      Per-point values change how every deformer is written.
      DecidedReserve the diamond and the port type now. Build them after the value lane ships and is measured.
