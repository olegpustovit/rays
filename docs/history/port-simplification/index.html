The line savings are modest (about 4–5%). The larger gains are structural: OCaml closure records become Rust traits, atomics used to emulate shared arrays become plain disjoint slices, per-frame whole-model clones go away, test binaries stop being duplicated, and the edit-loop rebuild chain gets shorter.

Measured compile picture

Codegen dominates

85–95% of each Flow crate's build time is codegen at opt-level=1. flow_check is the outlier: 2.0 s of codegen per 1k lines, against 0.5–0.65 s for flow_ir and flow_sop, and 14 crates depend on it. Something in it expands badly, and cargo llvm-lines would show what. The tool is not installed yet.

Critical path

rays_math → rdk_core → rdk_geom → rdk_ops → rdk_boolean → rdk → sop → flow_sop → editor_document → flow_native → rays_editor → rays_bin. That is 12 crates built one after another, about 0.5–1.7 s each, mostly frontend. Touching flow_ir takes 3.8 s.

Generics are not the problem

The shape gate already keeps generics and macros rare: at most 28 generic functions in any crate. Most of the remaining type bloat is closure types. There are about 230 in the OGPU driver records and about 50 in Flow's GPU records. A single concrete map type also gets compiled separately in every crate that uses it: flow_sop uses 57 such types.

Largest files

flow_sop/lower.rs 5.8k lines, flow_ir/packed.rs 5.4k, rdk_ops/subdivide_refine.rs 5.1k, flow_eval/eval.rs 4.8k, renderer/scene_execution.rs 3.7k, flow_check/workspace.rs 3.7k. An edit inside any of them recompiles one large unit.

Why flow_check compiles slowly (from reading the code): the built-in op table in op.rs is built at runtime. array_ops alone has 47 closures, and there are 77 Arc::new(|…|) bodies in all, each with owned String/Ty signatures and their drop and cleanup code. workspace.rs has 14 different B-tree map and set types, and Cx.env: Rc<BTreeMap<String, Info>> is copied whole for each scope. term_arena derives Debug/PartialEq across 36 table types. Per byte of source, the outlier is still about 2.5×.

In one run, touching rays_math took 41 s instead of 7.6 s because the incremental caches of the Flow crates were stale. If something regularly invalidates the shared target/, such as a build with other flags or another profile, that one problem costs more than every other item on this page combined. Find the cause first (B0).

Regression guards

  • Per frame: one serialized GPU cargo t case in rays_editor, built on the isogrid_orbit harness. Warm 30 frames of basic.rays, then assert that mem_sys::alloc_count() over the next 30 frames stays at or below about 3,300 per frame (and add a bytes bound). Add a second case for the empty editor at or below about 1,200. Tighten the limits after each fix. On failure, turn on mem_sys::TRACE so the report names the sites.
  • Per cook: add thread-local allocation counters to mem_sys (about 8 lines) and a test_alloc_budget.rs file in flow_sop: (a) a walker loop with field access, destructuring and a closure, for M11, M12, M15 and M16; (b) an aliased 4096-element store, for M10; (c) a round trip of P, Cd and a text attribute on a 100k-point grid, for M13 and M19; (d) peak bytes during subdivide, for M17 and M18. Limits may only go down, the same rule memory-budgets.sexp follows.

Int becomes plain i64

Owner decision: drop the signed 63-bit Int that was inherited from OCaml. Int becomes a native i64 with two's-complement wrapping, and the spec changes to match. Every Lisp Int operation goes through one function, flow_syntax::packed_ops::integer_apply, so this is mostly deletion.

What gets simpler

  • packed_ops moves to plain wrapping_*; wrap63 in flow_check is removed.
  • The ocaml_int crate is deleted; 5 of the 8 crates that depend on it never use it.
  • Five MAX_INT/OCAML_* constants become i64::MAX/i64::MIN.
  • Four Int literal parsers drop the 63-bit sign fold and become i64::from_str_radix.
  • MSL: wrap_integer is removed. SPIR-V: wrap_integer and the shr mask are removed. WGSL: i63 is removed. JS: BigInt.asIntN(64), and the fast path drops its <<1>>1.
  • Fixes three existing bugs: abs(-2^62) goes out of range in packed.rs:2731; literals between 2^62 and 2^63−1 come out as Float in some paths and as Int in others; and a CPU/JS mismatch in color/byte.

What needs care

  • i64::MIN becomes a value Lisp can reach. Rust / and % need wrapping_div/wrapping_rem. MSL needs a b==-1 guard (it is undefined behaviour in C++). About 25 RDK negate, abs and square guards move to checked_*.
  • WGSL i64_divmod uses a signed compare that breaks for |b| = 2^63. Switch it to an unsigned i64_ult.
  • Keep rand/at, Rand.float_at and the geometry hashes exactly as they are. They become named hash functions that keep a wrap63 helper in rays_math::hash. JS randAt needs its own w63. Seeds at 2^62 and above alias other seeds; this is deterministic and goes into the spec.
  • The INT63 test constant appears three times (flow_ir, flow_gpu, flow_web). All three must change together.

Golden impact: text-only regeneration of about 104 JS goldens, 19 of 24 .metal fixtures and their .spv files. No pixel, geometry or sketch golden should change. Steps: (1) update the spec text in core.md, flow.md and gpu-codegen.md; (2) change the Rust core and add one table test: MAX+1=MIN, MIN/-1=MIN, MIN%-1=0, shl(1,63)=MIN, shr(-1,1)=MAX, abs(MIN)=MIN; (3) move wrap63 into rays_math::hash, delete ocaml_int, and check that the hash tests are unchanged; (4) move the RDK guards to checked_*; (5) update MSL/SPIR-V and refresh their fixtures on Metal; (6) update WGSL, JS and the web runtime, and add JS cases for int/div(min,-1) and rand/at.

Plan in six waves

Wave A · deletions and dependency hygiene · low risk

Pure removals; goldens unchanged

  • Delete the unused crates rays_collections and rays_hash (about 1.5k lines). With them gone, the shape gate's generics rule becomes a plain ban.
  • Delete the 48 uncalled sop::support functions, rdk_ops::edge_transport, five empty rdk_ops modules and 16 unused rdk re-exports (about 550 lines).
  • Remove unused dependencies: ocaml_int from four UI crates, flow_eval from pxui_graph, and editor_core and input from rays_bin.
  • Remove the three gpu_suite_*_b test targets and shard(). cargo t already runs one process per case.
  • Delete the 66 MAX_ARRAY_LENGTH checks that emulate OCaml's array-size limit (about 250 lines). Keep the key-packing overflow checks.
  • Merge the six MD5 copies into rays_math::hash. Make region_snapshot test-only. Make the Editor::Private forwarders and pxui_graph accessors used only by tests test-only too.
About −3.5k lines, 2 fewer crates, fewer test links. One commit per bullet, each followed by cargo t on the crates it touched.
Wave B · build speed · measure each change

Fix the edit loop before refactoring

  • B0: find what invalidates incremental caches in the shared target (the 41 s vs 7.6 s run above).
  • B1: run cargo llvm-lines -p flow_check and fix whatever is causing its codegen outlier.
  • B2: compare opt-level=0 against 1 for the UI crates that are off the rays check hot path: rays_editor, pxui_graph, editor_document, flow_graph and flow_native. These used about 30 s of codegen. Keep the change only if debug run speed holds.
  • B3: merge the gpu_suite_t1..t6 and qualification tests into one gpu_editor test binary and share one test-support module. That is 10 test links reduced to about 2.
  • B4: add a buildtime canary for the editor chain (rebuild rays_bin after touching flow_ir).
  • B5: move flow_sop's catalog, manifest, port and network types into a small crate below it, so editor_document no longer waits for flow_sop. Delete the re-export-only rdk crate.
Expected (estimate): 10–15 s off the cold cascade, about 1–1.5 s off each mid-level edit, and much faster test builds.
Wave M · allocation quick wins · low risk, measured

Add the guards first, then cut allocations

  • Add the per-frame and per-cook allocation guards with today's limits, and delete the mem_sys TEMP sampler (M20).
  • Fixes that take one line to a few dozen: M10 (O(n²) stores), M11 and M12 (allocations in the walker and in recording), M2 and M9 (borrow instead of clone), M4 (check whether the scope changed before doing the work), M6–M8 (renderer scratch reuse and allocation-free keys).
  • Then M1 (interned evaluator routes), M14 (40-byte Value) and M16 (closure environments). Run the sequential/parallel equality tests after each.
  • M13 then M19 (one array type for attributes and Lisp values, then flat text rows). M3, M5, M15 and M17 land with C6, C1 and C3.
Target (estimate): basic from about 3.2k to under 2k allocations per frame, gpu_sea from about 33k to under 15k. Lower each guard's limit as fixes land.
Wave I · Int becomes i64 · medium risk, text-only goldens

Spec change, then each target

  • Follow the six steps in the "Int becomes plain i64" section above. This runs in parallel with Wave A, since it also deletes ocaml_int, which replaces that item in C10.
About −150 lines net, one crate fewer, and three existing bugs fixed. Hashes are frozen, so pixel and geometry goldens stay the same.
Wave C · replace OCaml-port patterns · medium risk

Same behaviour, written for Rust

  • Turn closure records into traits: OGPU's Driver* records (97 Box<dyn Fn> fields across three backends) and Flow's Resident/Gpu::* records (about 35 fields, a guard cloned 13 times).
  • Replace the atomic AInts/AFloats/ABytes arrays and about 70 per-range mutex slots with one par_fill over disjoint chunks_mut in rdk_core::support.
  • Unify the attribute gather/select code (four implementations, about 40 matches over all eight storage types) on float_planes plus one select.
  • Return Result from materialise and delete the three catch_unwind calls. Narrow guarded_force.
  • Editor: reducers take &mut t, the pane uses borrowed views, and panel_map becomes a plain struct. This removes the whole-model clones made several times per frame.
  • Merge thin crates: ogpu→ogpu_core, native_layer_token→_sys, vulkan→ogpu_vulkan, ocaml_int→rays_math::int63, runtime_input→runtime, the six SDL satellites into sdl3/sdl3_sys, and cfmt_sys→cfmt.
About −5…7k lines and about 13 fewer crates. Debug execution should also get faster: no per-element atomics, no per-frame clones, and painters allocated once instead of twice. Run GPU checks per backend change.
Wave D · deliberate golden refresh · higher risk

Drop OCaml ordering, error text and the duplicate interpreter

  • Write register, ID and evaluation order in natural Rust order, removing about 30 "match OCaml order" workarounds. Replace the 47 Vec::insert(0,…) list-prepend copies. Refresh the MSL, SPIR-V, WGSL and snapshot goldens in one commit.
  • rdk errors become {op, code: enum, message}. This deletes 22 error re-coders, 71 unwrap_or_else(|bad| bad) calls and the string-compared "cancelled" check.
  • Merge the two WGSL printers into one with a precision flag, as the Metal side already does.
  • packed.rs: keep the typed CPU engine and turn the float engine into fast paths inside it (about −1k lines). Do this only behind bench_core showing no regression.
  • Last: merge Value's four float-array variants into Floats(width, …), which touches 90 sites in 23 files.
About −2.5…3.5k lines. Each bullet ships with its golden refresh and a written diff review.

Checked and kept

  • Execution tiers (eval walker → core_exec → packed → GPU): each tier has different capabilities.
  • The four kernel printers (MSL, SPIR-V, WGSL, JS) already share kernel_layout::Visit.
  • Type erasure with dyn Any in lru/mem is the intended way to avoid generics.
  • Triangulation and the 3D bounding-volume trees are already shared. The shortest_paths heap needs decrease-key.
  • Rc<RefCell> in the GPU owners stays, because GPU state is confined to the main thread.
  • The crate boundaries of editor_core, editor_document, editor_commands and the pxui_shell intents are real.
  • mem_sys, metal_sys and vulkan_sys hold real platform code.

How to run it

  • One stage per commit. Run cargo check -p while editing, then cargo t -p on the touched crates and their consumers, then native and GPU checks before committing. cargo run -p gate -- deps after any boundary change.
