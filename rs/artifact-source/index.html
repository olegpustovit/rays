1. Shape of the rewrite

~270kOCaml product lines (409k with 140k test lines)
60dune libraries in 12 dependency layers
32kC / ObjC / C++ bridge lines, reused unchanged
32kRays Lisp lines, unchanged (the contract)
  • Separate tree, no mixed binary. A Cargo workspace at rs/ in this repo. The OCaml tree stays the shipping product and the oracle until cutover. No OCaml↔Rust FFI: glue for 400k lines of boundaries would be throwaway work and a second source of bugs.
  • Translate, don't redesign. One OCaml module becomes one Rust file with the same name, the same public functions and the same behaviour. Redesigns (memory plan stages, new caches) wait until after cutover. The single exception is the path-tracing gap in §6, which is closed in OCaml first so the port stays a translation.
  • Strong agents set shapes, cheap agents fill bodies. A strong agent turns each library's .mli files into a compiling Rust skeleton (all types, all signatures, todo!() bodies, fixed Cargo.toml). Cheap agents then fill one module each, in parallel, touching one file and its tests. Nobody but the skeleton owner edits lib.rs, Cargo.toml or a public signature.
  • The oracle decides. A unit is done when its ported tests and its oracle fixtures pass byte for byte. End-to-end goldens (Lisp output, shaders, web export, pixels, path-traced images) gate each wave and the cutover.
  • Feature freeze on OCaml during the port. Bug fixes only; each fix lands with a fixture, so the Rust side inherits it.

3. Build speed

Budgets

Targets measured in Wave 0 on the M1 Air and the Windows box. If Wave 0 cannot meet them, stop and revisit before porting further (see §12).

MeasureBudget
cargo check -p <leaf> after a one-line body edit≤ 1 s
One-line edit in a middle crate, rebuild + run its tests≤ 5 s
Focused crate run, build + all its tests≤ 15 s
One test≤ 5 s, hard kill
Clean debug build of the whole workspace≤ 120 s
Whole workspace tests, warm≤ 60 s

Structure that keeps rebuilds small

  • Many small crates. One crate per dune library, and no crate over about 8k lines. The large libraries are split along their own module DAG (ocamldep order; OCaml modules cannot be cyclic, so the split is always possible): flow (16k) → flow_syntax, flow_check, flow_eval; flow_ir (18k), flow_sop (15k), sop (11k), rdk_boolean (10k) and rays_editor (23k) the same way. The skeleton agent picks the cut.
  • One test binary per crate. Unit tests live in #[cfg(test)] mod tests inside the source file; oracle fixtures in a single tests/parity.rs. No other tests/*.rs files: each one is a separate link, and linking dominates incremental test time.
  • No generics in public APIs, no proc macros (§7). Monomorphisation and macro expansion are where Rust compile time goes; avoiding both keeps per-crate compile cost close to the line count.
  • No external crates except cc (build dependency for the C bridges). Hashing, sexp reading, PNG write, JSON for tooling: small std-only crates in the workspace.
  • Thin public surfaces. A body edit that keeps signatures rebuilds only that crate; dependents re-link only. Rust only rebuilds dependents' metadata when a public signature changes, and signatures are frozen by the skeleton.

4. Test runner: cargo t

rs/tools/t is a std-only runner, not cargo-nextest. It builds selected test executables with cargo test --no-run, discovers test names, and executes each case in a separate child process to enforce per-test timeouts and collect timings.

# rs/.cargo/config.toml
[alias]
t = "run -q -p rays-t --"

# rs/tools/t/src/main.rs
const TEST_TIMEOUT: Duration = Duration::from_secs(5);
const SLOW_TEST_TIMEOUT: Duration = Duration::from_secs(60);
const WHOLE_RUN_DEFAULT: Duration = Duration::from_secs(60);

# examples
cargo t -p param
cargo t -p cfmt --profile slow -- --ignored

What cargo t does:

  1. Runs cargo test --no-run, gets test names from each executable's --list output, then runs each name with --exact in its own child process.
  2. Kills a test after 5 s by default (60 s with --profile slow) and the whole run after 60 s by default (RAYS_T_TIMEOUT, 0 = none); exits 124 on timeout.
  3. Prints wall time and the five slowest tests; appends date, crate, test, seconds to rs/target/t-times.tsv.
  4. Queues before Cargo with a lock in rs/target/, runs ordinary tests in parallel, and serializes tests named window_* or gpu_*.

Rules: a default test that hits 5 s is a defect, never a raised limit. Ported OCaml tests that are slower today (rows in specification/test-times.md) are shrunk while porting or explicitly moved to the slow run with an #[ignore = "slow"] reason. Golden corpora are one test per file. The runner discovers tests from the compiled executable; it needs no generated test list or build script.

5. Parity: how regressions are caught

Four layers, from cheapest to widest. A unit needs L0 and L1; a wave needs L3; cutover needs all of them.

L0 Ported tests

Every OCaml test file beside a module (450 files, 140k lines) is translated with the module, assertion for assertion. A cheap agent may not drop a test; if it cannot port one, it writes a waiver line with the reason and a strong agent reviews it.

L1 Oracle fixtures

  • A test-only OCaml library per wave, rs/oracle/<lib>_capture.ml, built by dune, calls the library's public functions on chosen inputs and prints input → output cases into rs/fixtures/<crate>/<module>.sx.
  • Format: s-expressions, one case per form. Floats are written as their 64-bit pattern in hex (#x3ff0000000000000), so comparison is exact and print-format-free. Strings are byte-escaped.
  • Inputs come from three places: values recorded at module boundaries while running every sketch in sketches/ for a few Fixed dt frames (a capture hook in test builds only); the existing OCaml tests' inputs; and seeded random inputs for pure libraries (rays_math, rdk_core predicates, the Lisp reader and printer, flow_ir passes).
  • Fixture files are written only by the oracle tool and are read-only to porting agents. A fixture change after the fact needs an entry in rs/port/accepted-diffs.md signed off by a strong agent and the owner.

L2 Differential fuzz (slow profile)

For pure libraries, an OCaml oracle executable answers s-expression requests on stdin. A Rust test drives the OCaml oracle and the Rust port with the same seeded random cases and stops at the first difference, printing the input. Runs nightly and before each wave closes; never in the edit loop.

6. Path tracing on Metal and Vulkan

Critical: the metal and vulkan crates must both run every path-tracer feature. Today they don't: Vulkan traces triangles and instances with ray queries, but lib/ogpu_vulkan/backend.ml:541–562 rejects motion triangles, motion instances, curves and procedural boxes with E.Unsupported, and its caps report ray_tracing_motion = false.

Order

  1. PT0, before the port, in OCaml (strong agent, Windows box). Close the four Vulkan gaps in lib/vulkan/vulkan_bridge.c, ogpu_vulkan and the SPIR-V printer. This gives the rewrite a Vulkan oracle for every feature, and keeps the Rust port a pure translation. Metal's converged images are the oracle for PT0 itself.
  2. PT1, conformance suite first. Extend ogpu_conformance with deterministic ray-set tests per geometry kind: a fixed list of rays, expected hit/miss, t, primitive id, instance id and barycentrics. Both backends must agree with each other within 1e-5 relative on t and exactly on ids. One test per kind, each under 5 s.
  3. PT2, image parity. For each scene in test_pathtracer, test_scene, test_world and sketches/pathtracer.rays: fixed seed, 256², 64 spp. Pass when the per-pixel difference of means lies within 3σ of the per-pixel variance both renders report, on 99.5% of pixels, and the image mean differs by under 0.5%. A converged Metal render (offline, 4096 spp, checked in as an EXR-free float dump) is the long-run reference in the slow profile.
  4. PT3, performance. Budgets from specification/pathtracer.md on the M1 (e.g. 2001 instances + 20k triangles: move + flush about 2 ms) and from specification/vulkan/rtx2080ti.json on Windows. Rust must match or beat the OCaml numbers.
  5. PT4, the Rust crates. In Wave 3–7, ogpu_metal, ogpu_vulkan and rays_pathtracer are ported by strong agents only. G8 runs the PT1–PT3 suites on both machines; Wave 7 does not close and cutover does not happen until G8 is green on both.

The C/ObjC bridges (metal_bridge.mm, vulkan_bridge.c, vma.cpp, volk) are compiled by cc in each sys crate's build script and called through extern "C". The Metal binding registry generator (lib/metal/gen) gets a Rust emitter beside its OCaml one, so the Rust declarations are generated, not handwritten, as today.

The queue

rs/port/queue.tsv, written by cargo run -p port -- plan from ocamldep: one row per OCaml module, columns id, ocaml_file, rust_file, crate, depends_on, lines, tier, status, owner. Modules over 600 lines are split into several units by function groups (the skeleton agent lists them). port next hands out a unit whose dependencies are all done; port claim, port done and port fail update the row in one commit on the agent's branch.

Tiers

Strong agentsCheap agents
Wave 0 tools and helper crates; every skeleton and crate split; parallel, mem, the Lisp evaluator core, the Format printer; all *_sys crates, ogpu_* and rays_pathtracer; any unit touching Gc, Weak, Obj, Marshal, effects or unsafe; failed units; accepted diffs; waiver reviewModule bodies; translating each module's tests; oracle capture functions for their module; nothing else

Brief for a cheap agent

Port unit {id}: {ocaml_file} (lines {range}) to {rust_file}.

Read:  {ocaml_file}, its .mli, its test file {ocaml_test}, and the Rust
       skeleton {rust_file}. Read rs/port/COOKBOOK.md and TRAPS.md.
Write: only {rust_file} (bodies and #[cfg(test)] mod tests), and
       rs/oracle/{lib}_capture.ml cases for this module.
Never: change a signature, lib.rs, Cargo.toml, a fixture file, or any
       other file. Never add a crate, a generic, a macro, a lifetime on
       a struct, unsafe, or a panic for control flow.
Translate every function and every test one for one. Keep names.
If a construct is not in the cookbook, stop and run `port fail {id}
""`. Do not invent a translation.

Done when, with the times printed:
  cargo check -p {crate}
  cargo t -p {crate} {module}          # ported tests, each under 5 s
  cargo t -p {crate} parity::{module}  # oracle fixtures, exact
  cargo run -p gate -- shape {crate}
Then `port done {id}` and report the four commands' wall times.
After one failed retry on the same error, `port fail {id}` with the
error text. Do not keep trying.

Why parallel work does not collide

  • A unit owns exactly one Rust file. lib.rs, Cargo.toml, public signatures and fixtures belong to the skeleton owner and are frozen before units are handed out.
  • Each agent works in its own git worktree on port/<id>; the merge queue rebases and reruns the unit's gates, one merge at a time.
  • Every merge is one commit, so a bad unit is one revert. Wave ends are tagged.
  • Every agent in the same worktree goes through cargo t, which queues before Cargo's lock, like tools/check.exe today.
